## نتائج معايير القبول

الوكيل يضيف هنا كل متطلب انتهى، ونتيجة كل معيار قبول فيه.

| المتطلب | المعيار | الطريقة | النتيجة |
|---|---|---|---|
| CUS-013 | إضافة لغة جديدة وتغيير النصوص دون تعديل منطق التطبيق أو كتابة نصوص ثابتة | اختبارات آلية Vitest + استيراد موحد من `@mahallat/shared` | ناجح ✅ |
| ADM-034 | جميع القيم مرنة وتُقرأ بتدرج (متجر ← تاجر ← مدينة ← عام ← افتراضي) دون تحديث الكود مع رفض القيم الشاذة | اختبارات آلية `tests/supabase-core.test.ts` لدالة `get_setting` والـ triggers | ناجح ✅ |
| ADM-002 | سجل التدقيق يوثق التغييرات بالقيمة قبل وبعد، ويمنع التعديل أو الحذف منعاً باتاً | اختبارات آلية على `audit_log` وقفل `prevent_audit_log_modification` | ناجح ✅ |
| DSP-002 | تحديد حدود المدن جغرافياً عبر PostGIS ودالة `city_for_point` ترجع المدينة لنقطة داخلها | اختبارات آلية جيومكانية `city_for_point` بنقاط داخل وخارج المضلع | ناجح ✅ |
| ADM-001 (الأساس) | تجهيز الأدوار والصلاحيات (10 أدوار)، ودالة `has_role` وسياسات أمان RLS | اختبارات أمان RLS ومنع وصول المستخدمين العاديين للإعدادات وسجل التدقيق | ناجح ✅ |
| MER-040 | مدة تحضير المنتج لا تتجاوز 40 دقيقة إلا لمتجر لديه صلاحية التجاوز | اختبارات آلية في `tests/stores-menu.test.ts` وقفل Trigger | ناجح ✅ |
| MER-025 · REG-002 | البيانات الغذائية الإلزامية في المنيو (منع نشر الصنف غير المعفى الناقص للسعرات) | اختبارات آلية في `tests/stores-menu.test.ts` وقفل Trigger للنشر | ناجح ✅ |
| MER-002 | صلاحيات المنيو للتاجر وتحديث الأسعار (تطبيق فوري ضمن النسبة أو للصلاحية الكاملة، وتحويل للمراجعة عند التجاوز) | اختبارات آلية لدالة `submit_menu_item_price_update` | ناجح ✅ |
| MER-009 | نوع التشغيل والقسم (تغيير تصنيف المتجر لا يغير بنود العقد المالي إطلاقاً) | اختبارات آلية في `tests/stores-menu.test.ts` | ناجح ✅ |
| MER-046 | نوع المتجر عند الإضافة (المتجر غير المتعاقد لا يمكن إضافة أقسام أو أصناف له) | اختبارات آلية في `tests/stores-menu.test.ts` وقفل Trigger | ناجح ✅ |
| MER-001 | تسجيل التاجر والفروع (منع تفعيل فرع ينقصه مستند إلزامي ساري، وحماية سرية بيانات الفروع عبر RLS) | اختبارات آلية في `tests/stores-menu.test.ts` وقفل Trigger للمستندات | ناجح ✅ |
| ADM-001 | التحقق بخطوتين (AAL2) إلزامي للإدارة في RLS وحجب الأمور المالية عن موظف الدعم، ودعوة الموظفين | اختبارات RLS + دالة `admin_update_setting` وواجهة `/admin/login` و `/admin/users` | ناجح ✅ |
| ADM-034 | لوحة تحكم الإعدادات، التبويبات، عرض التخصيصات، واشتراط سبب التعديل وتأكيد المقارنة قبل وبعد | صفحة `/admin/settings` واختبارات آلية لدالة `admin_update_setting` وسجل التدقيق | ناجح ✅ |
| ADM-002 | لوحة سجل التدقيق للقراءة فقط ومحمية من الحذف والتعديل وفلاتر البحث بالتاريخ والنوع والجدول | صفحة `/admin/audit-log` واختبارات قفل RLS ودوال التدقيق التلقائي | ناجح ✅ |
| DSP-002 | رسم وتعديل حدود المدن كـ MultiPolygon جغرافياً، وتفعيل/إيقاف المدينة، وتطابق تغطية النقاط | صفحة `/admin/cities` واختبارات دالة `city_for_point` بـ PostGIS ST_Covers | ناجح ✅ |

- تم توحيد إصدار `react` على `19.2.3` في كِلا تطبيقي Expo (`apps/customer`) و Next.js (`apps/web`) لتفادي أي تعارض في حزم الـ Monorepo.
- تم إعداد مكتبة الاختبارات `vitest` بنجاح واجتازت جميع اختبارات اتجاه اللغات `packages/shared`.
- تم رفع ملف الترحيل وقاعدة البيانات والبيانات الأولية إلى مشروع Supabase السحابي (`delivery-dev`).
