## نتائج معايير القبول

الوكيل يضيف هنا كل متطلب انتهى، ونتيجة كل معيار قبول فيه.

| المتطلب | المعيار | الطريقة | النتيجة |
|---|---|---|---|
| CUS-013 | إضافة لغة جديدة وتغيير النصوص دون تعديل منطق التطبيق أو كتابة نصوص ثابتة | اختبارات آلية Vitest + استيراد موحد من `@mahallat/shared` | ناجح ✅ |
| ADM-034 | جميع القيم مرنة وتُقرأ بتدرج (متجر ← تاجر ← مدينة ← عام ← افتراضي) دون تحديث الكود مع رفض القيم الشاذة | اختبارات آلية `tests/supabase-core.test.ts` لدالة `get_setting` والـ triggers | ناجح ✅ |
| ADM-002 | سجل التدقيق يوثق التغييرات بالقيمة قبل وبعد، ويمنع التعديل أو الحذف منعاً باتاً | اختبارات آلية على `audit_log` وقفل `prevent_audit_log_modification` | ناجح ✅ |
| DSP-002 | تحديد حدود المدن جغرافياً عبر PostGIS ودالة `city_for_point` ترجع المدينة لنقطة داخلها | اختبارات آلية جيومكانية `city_for_point` بنقاط داخل وخارج المضلع | ناجح ✅ |
| ADM-001 (الأساس) | تجهيز الأدوار والصلاحيات (10 أدوار)، ودالة `has_role` وسياسات أمان RLS | اختبارات أمان RLS ومنع وصول المستخدمين العاديين للإعدادات وسجل التدقيق | ناجح ✅ |

## ملاحظات ومشاكل

- تم توحيد إصدار `react` على `19.2.3` في كِلا تطبيقي Expo (`apps/customer`) و Next.js (`apps/web`) لتفادي أي تعارض في حزم الـ Monorepo.
- تم إعداد مكتبة الاختبارات `vitest` بنجاح واجتازت جميع اختبارات اتجاه اللغات `packages/shared`.
- تم رفع ملف الترحيل وقاعدة البيانات والبيانات الأولية إلى مشروع Supabase السحابي (`delivery-dev`).
- تم توليد أنواع TypeScript لقاعدة البيانات وتصديرها من `@mahallat/shared` مع إضافة أمر `npm run db:types`.
- تم توثيق جميع المفاتيح والقيم في `docs/settings-keys.md`.
