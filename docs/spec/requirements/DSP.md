# التوزيع والمدن DSP

## DSP-001 · توزيع الطلبات

- **الأولوية:** أساسي للإطلاق

**القواعد**

- يعتمد المبرمج نظام التوزيع الذي يعمل به حالياً
- الحد الأدنى: مندوب واحد لكل طلب، داخل المدينة، وكل قرار مسجل
- بلا مندوب: تنبيه لغرفة العمليات بعد 5 دقائق مع إسناد يدوي، وإلغاء تلقائي بعد 15 دقيقة أو تحويل لاستلام ذاتي
- المستوى والدرجة يحددان أولوية العرض ( DRV-015 )

**معيار القبول**

- [ ] قبولان متزامنان يُسندان لواحد

## DSP-002 · المدن

- **الأولوية:** أساسي للإطلاق

**القواعد**

- المدير يرسم حدود كل مدينة، وهي الزون الافتراضي
- عند إضافة متجر وتحديد مدينته ينزل زون المدينة تلقائياً، وللمدير خيار رسم زون يدوي آخر للمتجر
- اختيارياً: زون محدد داخل المدينة لمندوب بعينه، ولا تصله طلبات خارجه
- إسناد يدوي برقم المندوب مع سبب

**معيار القبول**

- [ ] عميل خارج مدينة المتجر لا يطلب منه
- [ ] مندوب له زون محدد لا يُعرض عليه طلب خارجه

## DSP-003 · تعدد الطلبات

- **الأولوية:** أساسي للإطلاق

**القواعد**

- يقبل المندوب حتى 3 طلبات في الوقت نفسه، يستلمها ويسلمها في رحلة واحدة
- الطلبات المجمعة لا تُسند للمندوب إلا إذا كان العملاء داخل نطاق كيلو متر واحد من بعضهم
- الوقت المسموح يُحسب على مسار الرحلة الفعلي ( ORD-012 )
- العدد والنطاق مرنان من الإعدادات

**معيار القبول**

- [ ] عميلان بينهما 1.5 كم لا يُجمعان
- [ ] طلب رابع لا يُعرض على مندوب معه 3 طلبات

## DSP-004 · سقف المناديب في المدينة

- **الأولوية:** مهم

**القواعد**

- للمدير سقف لعدد المناديب الأحرار المتصلين في كل مدينة وساعة
- من يتجاوز السقف يُوضع في قائمة انتظار تُعلمه بالأوقات الأقل ازدحاماً

**معيار القبول**

- [ ] بلوغ السقف يضع المندوب التالي في قائمة الانتظار
